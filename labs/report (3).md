# Цель работы

Освоить работу с RAID-массивами при помощи утилиты mdadm.

# Ход выполнения

## Создание RAID-диска

### Проверка наличия дисков

Для проверки отображения ранее добавленных дисков использовалась команда `fdisk -l | grep /dev/sd`.  
В системе присутствуют устройства `/dev/sdc`, `/dev/sdd`, `/dev/sde`.

На каждом из дисков `/dev/sdc`, `/dev/sdd` и `/dev/sde` был создан новый раздел с помощью утилиты `sfdisk`.

![Создание разделов](Screenshot_1.png){ #fig:001 width=70% }

### Проверка типа созданных разделов

Команды просмотра типа разделов показали, что у созданных партиций установлен тип **83 (Linux)**.

Вывод списка доступных типов партиций, связанных с RAID, показал наличие типа:

**fd — Linux raid autodetect**

Для каждого из дисков тип раздела был изменён на **fd** — Linux raid autodetect.

![Изменение ID разделов](Screenshot_2.png){ #fig:002 width=70% }

### Проверка состояния дисков

Утилита `sfdisk -l` показала корректно созданные разделы на всех устройствах:  
каждый имеет размер около **511M** и тип **fd Linux raid autodetect**.

![Состояние дисков](Screenshot_3.png){ #fig:003 width=70% }

`mdadm --grow /dev/md0 --raid-devices=3`

![RAID 5 на трёх дисках](Screenshot_15.png){ #fig:208 width=70% }

- Здоровье массива: **clean**

После выполнения работы массив был удалён:

- Размонтирован  
- Остановлен

Также была закомментирована строка в `/etc/fstab`:

`#/dev/md0 /data ext4 defaults 1 2`

# Контрольные вопросы

**1. Приведите определение RAID.**
RAID (Redundant Array of Independent Disks) — это технология объединения нескольких физических дисков в единый логический массив для повышения производительности, отказоустойчивости или обеих характеристик одновременно.
Массив управляется специальным алгоритмом, распределяющим данные и контрольную информацию между дисками.

**2. Какие типы RAID-массивов существуют на сегодняшний день?**
Наиболее распространённые уровни RAID:

* **RAID 0**
* **RAID 1**
* **RAID 2** (практически не используется)
* **RAID 3**
* **RAID 4**
* **RAID 5**
* **RAID 6**
* **RAID 10** (1+0)
* **RAID 01** (0+1)
* **RAID 50**, **RAID 60**
* **RAID с hot spare** — массивы с резервным диском
* Программные и аппаратные вариации гибридных уровней

**3. Охарактеризуйте RAID 0, RAID 1, RAID 5, RAID 6. Опишите алгоритм работы, назначение и приведите примеры применения.**

### **RAID 0 — чередование (striping)**

**Алгоритм работы:**
Данные разбиваются на блоки и записываются попеременно на все диски массива.

**Преимущества:**

* Максимальная производительность: чтение/запись ведутся параллельно.
* Полный полезный объём равен сумме всех дисков.

**Недостатки:**

* Полное отсутствие отказоустойчивости.
* Отказ одного диска приводит к потере всех данных.

**Применение:**

* Временное хранение данных
* Видеообработка
* Кэш, тестовые стенды
* Сценарии, где важна скорость, а не сохранность

### **RAID 1 — зеркалирование (mirroring)**

**Алгоритм работы:**
Каждый блок данных записывается на два диска одновременно.

**Преимущества:**

* Высокая отказоустойчивость: выход одного диска не приводит к потере данных.
* Чтение может ускоряться за счёт параллельного доступа к зеркалам.

**Недостатки:**

* Полезный объём равен сумме дисков, делённой на 2.
* Повышенные требования к количеству носителей.

**Применение:**

* Серверы баз данных
* Веб-серверы
* Критически важная информация

### **RAID 5 — распределённая чётность (striping + parity)**

**Алгоритм работы:**
Данные и контрольные суммы (parity) распределяются по всем дискам массива.
При выходе из строя одного диска массив восстанавливается за счёт контрольных сумм.

**Преимущества:**

* Отказоустойчивость при выходе одного диска.
* Хороший баланс между объёмом, скоростью и надёжностью.
* Полезный объём равен сумме всех дисков минус один.

**Недостатки:**

* Потеря производительности при восстановлении.
* Не защищает от одновременного отказа двух дисков.

**Применение:**

* Файловые серверы
* Архивы
* Корпоративные хранилища среднего уровня

### **RAID 6 — двойная чётность (double parity)**

**Алгоритм работы:**
Хранит две независимые контрольные суммы, что позволяет выдерживать отказ двух дисков сразу.

**Преимущества:**

* Максимальная отказоустойчивость среди стандартных уровней.
* Полезный объём равен сумме всех дисков минус два.

**Недостатки:**

* Медленная запись из-за двойного расчёта контрольных сумм.
* Более высокая стоимость (много дисков требуется).

**Применение:**

* Большие корпоративные хранилища
* Системы, требующие высокой надёжности
* Серверы с большим количеством дисков
